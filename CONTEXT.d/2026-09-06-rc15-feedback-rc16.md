## 2026-09-06 -- rc.15 stability review: all ten findings closed for rc.16 (fix/rc15-feedback)

The independent Codex stability review of rc.15 (source pinned at 7ef62a2e) raised
ten findings, R1-R10. The owner-approved plan (v3) closes each at its cited
mechanism in ONE PR, one commit per finding (R6 and R7 share their helpers and
one commit), with every Codex characterization test flipped into a regression
test, mutation matrices per phase, and independent spec + quality reviews per
phase. This fragment records the decisions the build made beyond the plan's
literal text, and what is owed before merge.

### R1 -- container entry is proven from inside the container

- The entry command is `[sudo] <engine> exec -it [-w dir] <ctr> sh -c 'printf
  IN; CCC_ENTRY=<nonce> <shell>; printf OUT'` rather than the plan's `bash -c
  '...; exec bash'`: `sh -c` reads no startup file before IN (Codex plan-review
  condition 4), the shell runs as a CHILD so OUT is printed when it exits, and
  CCC_ENTRY lets the launch guard (`printf "$CCC_ENTRY" HERE`) re-prove the
  attached shell before ANY ordinary write. The guard runs twice: before the
  container setup and again before the claude command (review round 2: a
  detach between `setup ok` and the claude write printed no OUT).
- The unproven-entry hold is (10+1) x 1.5 s from the last output (16.5 s), the
  engine's start-up allowance on a host whose prompt cannot be stripped; the
  guard waits 5 s. The plan's "5 s probe wait" was the guard, not the hold.
- `start -ai` and unrecognised free text are never auto-promoted: the overlay
  asks for explicit consent (Launch anyway / Skip). A legacy free-text `docker
  exec` line is parsed (`-w` now recognised) and recomposed with the sentinel,
  keeping its shell; the SessionDialog gained a "Shell inside the container"
  choice (bash / sh) so a converted `sh` config is not stuck.
- ACCEPTED LIMITATION: a legacy free-text config with `-w` that was recorded as
  a HOST session before rc.16 is a container session now, so a detached row it
  left behind no longer matches it (end it from the sidebar) and SSH Persistent
  no longer applies to it, as for every container session. Documented in
  app-knowledge known issues.
- Live lanes T24 (cancelled sudo on a zsh `%` host, then Run again), T25 (zsh
  login shell) and T26 (`start -ai` consent) are in the docker lane; T24/T25
  switch the Rocky user to zsh per test with a breadcrumb and a loud revert.
  Rocky needs zsh installed first (the lane refuses to install packages).

### R2-R5 -- accounts

- R2: the follower is still stamp-based (the credential file's mtime, seen
  unchanged on the poll after it moved). Codex's plan review returned CLOSES
  on that design; a content-derived credential/identity generation was not
  built. ACCEPTED LIMITATION.
- R4 (owner decision, plan Q1 = a): the capture path restores the source
  profile's IDENTITY ONLY (`restoreProfileIdentityFromCanonical`): the canonical
  `.claude.json` goes back with token-bearing keys stripped and the home's
  `.credentials.json` is removed, so the account reads Sign in rather than
  running on a token it may have spent. `restoreProfileHomeFromCanonical` keeps
  no production caller; Codex's helper-level "F6 residual" case therefore still
  passes by design -- the production path is what changed, and the flipped test
  drives the real capture IPC.
- R3: both local spawn paths defer while the profile is mid-refresh (hold first,
  wait, re-enter with a main-internal `refreshAwaited` flag). A kill during the
  wait cancels it; writes during the wait are dropped and logged, never queued.
  The exit of the PTY a parked spawn REPLACED is stale (the parked spawn is the
  session's next process); its teardown travels with the wait and runs once if
  the wait is cancelled or the re-entry fails without a PTY. Quality round 3:
  a spawn of the same id that finds a parked wait supersedes it -- cancel and
  carry the teardown, never run it there, because that reported an exit and
  wiped the canvas stamps pty:spawn had just written; a re-entry that throws
  AFTER registering its PTY leaves that PTY as the session; a superseding
  spawn that throws BEFORE it has a PTY runs the carried teardown once
  (spawnPty is now a thin wrapper around spawnPtyResolved for that reason).

### R6, R7 -- lifecycle

- The App.tsx close/startup handlers delegate to three plain helpers in
  `session-persistence.ts` (`loadSavedStateAtStartup`, `closeWithNoSessions`,
  `discardAndClose`) and `onAllWindowsClosed` in `window-close-coordinator.ts`,
  which is what made the behaviour unit-testable without rendering App. Codex's
  AST-driven lifecycle cases fail against rc.16 for that structural reason as
  well as the behavioural one; the flipped tests cover both startup shapes and
  the close-before-answer exit on the helpers, and a wiring test (the App.tsx
  and index.ts callbacks compiled from the source with esbuild)
  covers Resume, Don't open and Close sessions as App wires them. The owner's
  native macOS check is owed before merge.

### R9 -- late output from a replaced local PTY

- The stale EXIT of a replaced PTY was already suppressed by a process-identity
  check (rc.14 F8); R9 carries the SAME `ptySessions.get(sessionId)?.ptyProcess
  !== ptyProcess` guard on the DATA callback, so a restart's old process cannot
  feed the new terminal or its session-id-keyed watchdog. The guard sits at all
  three `onData` sites (local, SSH, Codex-provider); the flipped test covers the
  local and SSH branches and a killed-no-replacement case. The Codex-provider
  branch is the same one-line guard, asserted by inspection rather than a
  dedicated case (its spawn path is harder to drive headless) -- a documented
  coverage edge, mutation P3-8 proving the tested branches.

### R8 -- tmux liveness classification

- The probe runs `ls` first and prints FOUND with its exit status and captured
  output; only status 0 (a listing) or tmux's own "no server" phrasings are
  authoritative. Any other failure, even beside a candidate that answered,
  leaves the host UNVERIFIED (offered with the "could not verify" note). The
  flipped tests run the PRODUCTION builder under a real POSIX sh against
  synthetic tmux binaries (Codex 4.2). Live lane T27 (Pi, a shim at the staged
  candidate path) is in the Pi lane for the matrix.

### R10 -- canvas resume reads every artefact run and the full review debt

- One predicate (`isSettled`) for the resume list, the resume action and the
  completion guard's version/debt terms. A rejection counts as reworked once a
  LATER LIVE RUN OF THE SAME KIND carries a decision: a plan rendered after a
  design starts a new run in this history (artifactRuns breaks on the kind
  change), and its approval is the rework the rejected plan waited for. Archived
  runs owe nothing (Codex condition 3) but an archived approval still counts as
  decided; a live show-and-tell-only run is undecided. The debt oracle is built
  by the session link from the review store (draft, open, answered notes, live
  rounds; an unreadable store is debt). Mark complete names a rejected,
  unreworked artefact; the user's force passes it. Mark complete shares the
  predicate's TERMS (open versions, rejected-unreworked runs, the four debt
  counts) rather than calling isSettled, because its refusals name the term;
  the one pre-existing disagreement left is an agent-chat sign-off, which the
  guard refuses for an AGENT completion and isSettled does not read (follow-up).

### ADR-009 adversarial review (this PR)

- Four attackers (opus for R1 injection; sonnet for credentials/bypass, blast
  radius, design/coverage). The pass found real defects in the change and they
  were fixed in this PR, each with a baseline-red regression test and a
  fix-revert mutation (scratchpad `mutate-adv.py`):
  - **R1 (BLOCKER):** once a session was proven inside the container, a
    `failEntry` cleared `inInnerShell` and re-opened the saved HOST sudo secret
    to a `[sudo]` prompt the still-attached container printed (a forged OUT, a
    `su -`, a guard timeout, or a prompt coincidence). A sticky
    `containerEverEntered` latch now gates the sudo auto-answer off for good once
    entry is proven.
  - **R4 (BLOCKER):** `stripIdentityTokens` only reached the top level and
    `oauthAccount`, so a nested `mcpServers.<name>.env.<TOKEN>` rode back into
    the "token-free" home. It now strips by key name at every depth.
  - **R4 (MAJOR):** the capture-detected IPC gated only on "some session watches
    this profile", so a renderer naming any watched session could capture that
    account and (since R4) wipe its credentials. It now requires a real
    new-account detection (`detectedNewAccountEmail`). And a failed credential
    clear (a directory at `.credentials.json`) is handled: the file is removed
    recursively, or the identity is stripped so the home reads Sign in rather
    than the captured account.
  - **R3 (BLOCKER):** `killAllPty`/`gracefulExitAllPty` ignored a spawn parked on
    a refresh wait, leaking its hold and letting its deferred spawn start a PTY
    behind a destroyed window. Both now sweep the parked waits; the deferred
    re-entry also refuses to spawn into a destroyed window.
  - **R10 (MAJOR):** archiving the approved REWORK reintroduced the rejected
    plan's refusal (`rejectedRunAnchorsOf` filtered archived runs out of the
    rework scan). The scan now runs over all runs; only the emit skips archived.
  - **R8 (MINOR):** the tmux probe's connection-error text is now read under
    `LC_ALL=C` so a non-English remote locale cannot make an empty host read
    unverified. **Schema (MINOR):** the top-level `elevated` spawn option is now
    declared in `spawnOptionsSchema` (it was read by pty-manager but only
    validated under terminalOptions). **R7 (data-loss):** a Resume whose restore
    threw left the live set empty with the prompt cleared, so a close then wiped
    the saved file; a `restoreUnsettledRef` guard keeps the file until the
    restore lands.
- Round 2 (fresh attackers re-attacked the round-1 fixes): the security
  invariants held, and two issues were found and fixed. (a) The recursive strip
  over-stripped -- it dropped DATA-MAP keys (a `projects` path or `mcpServers`
  name containing "secret"), losing folder-trust/allowedTools; the recursion now
  spares the immediate children of `projects`/`mcpServers` while still stripping
  token FIELDS deeper. (b) `killAllPty` cancelled a fresh parked wait (no
  predecessor teardown) without telling the renderer, stranding the card on the
  non-quitting update-install path; `killPty` now emits a synthetic exit through
  the window stored on the wait. Two residuals are documented, not fixed: the
  name-based strip cannot catch a token VALUE under a clean key name (pre-existing,
  and it is user-global MCP config, not an account credential), and the lifecycle
  wiring test's source-marker match is CRLF-sensitive on a Windows checkout
  (pre-existing; CI runs LF -- a `.gitattributes` follow-up).
- The audited PASS marker is the first comment on the PR. This change also
  touches the SSH statusline live-matrix blast radius (pty-manager SSH branch,
  ssh-liveness), so that manual gate is owed too (above).

### Codex PR600 implementation re-review (round 3) and the R1 re-attack follow-ups

- Codex re-reviewed the PR head (`7565739c`) against its 21 cases and the plan
  conditions and returned five findings plus a Windows-CI shell fixture; all
  five are closed in `fc846de3` (tests isolated in `08345934`). (1, P1) The
  after-entry watch stood down at `claudeSent`, 200 ms before the claude
  command was actually written, so an OUT or a plain host-back detach in that
  window still let the command land on the returned host: the watch now gates
  on `claudeWritten`, and `deferredEntryWritePending` makes a host prompt
  returning during either deferred write (setup 300 ms, claude 200 ms) fail
  the entry so the pending write bails. (2, P1) A genuine IN in the same chunk
  as an engine diagnostic returned before the sudo latch closed, and a sudo
  answer already scheduled was never re-checked: the IN latches
  `containerEverEntered` before the engine-error return and the delayed sudo
  write re-checks it. (3) A FRESH deferred spawn (R3) that failed with no PTY
  told the renderer nothing: it now emits `pty:exit` and drops the canvas
  stamp. (4) `restoreUnsettledRef` started false, so a close during the startup
  load could still wipe the saved file: it starts true and clears only on a
  positive load. (5) The Mark-complete force path did not name the rejected,
  unreworked version: `describeForceClosures` carries
  `rejectedUnreworkedVersionIds` and the button names them. The
  container-entry shell-compat CI fixture is deterministic (it probes whether
  the chosen shell pre-sources `$ENV`/`$BASH_ENV`).
- One opus R1 attacker re-attacked those fixes: PASS, with one MINOR -- the
  deferred writes were anonymous timers that `failEntry` never cleared.
  Closing it (`ce1f70c1`) showed the consequence was worse than a duplicate
  setup blob: a Run again inside the 200 ms claude window resets
  `runtimeEntryFailed`, so the stale claude timer typed the command onto the
  HOST before the new exec was even out; and `claudeSent` was never un-latched,
  so after an OUT in that window the next attempt could not launch Claude at
  all. The pending write now has an owned handle; `failEntry` and `destroy`
  cancel it, and `failEntry` un-sends an unwritten claude command.
- The independent spec/quality review of that fix (PASS-WITH-NITS) found
  `skip()` ("Manage manually") still left a scheduled write armed -- reachable
  because an unverified Launch anyway schedules the setup synchronously with
  the Skip button live -- and a one-round R1 attacker of the result found that
  a Skip inside the claude window left a later Launch stranded behind an
  answered guard (the container leg of `launchClaude` had no "setup already
  done" route). Both closed (`e0959de7`, `d6ce3c46`): `skip()` withdraws the
  pending payload and resets its latches (the setup latch and its timeout,
  `claudeSent`, `claudeReproven`); a relaunch with the setup done goes to
  `proceedAfterSetup`, which re-proves the shell first. The attacker confirmed
  the closure. Its two NOTEs are pre-existing and documented, not fixed: the
  tmux-wrapped bookkeeping (`sshTmuxWrappedBySession`, the session-info emit)
  is set before the deferred claude write, so a withdrawn write leaves
  close/quit detaching a tmux that was never created until the next launch
  re-evaluates it; and `writeContainerSetupCmd`'s catch fails the flow without
  releasing `containerSetupSent` (self-healing at the 10 s setup timeout).
- Matrix at the final head (scratchpad `mutate-adv6.py`, 16 mutants): 15
  killed, 1 defence-in-depth survivor -- the schedule-time predecessor cancel
  is redundant with `failEntry`'s because the two writers are sequential by
  construction (removing both is killed). Seven regression tests in
  `pr600-r1-lifetime.test.ts`, each red before its fix. The ADR-009 PASS
  marker was re-issued for the new head (the first-comment marker covered
  `7565739c`).

### Codex PR600 final re-review (round 4): one P2 availability regression, closed

Codex's final bounded re-review of head `24d560b7` (code `d6ce3c46`) confirmed
both P1 issues and all five original findings CLOSED, and returned ONE new P2:
the ADR-009 finding-1 deferred-write host-back hint cancelled a HEALTHY launch
when the container's prompt is byte-identical to the host's. The hint tested
`isHostBackLine` without the distinct-inner-prompt guard the older idle
host-back hint carries, so a genuine IN + HERE followed by the healthy
container's own prompt in a later PTY chunk read as a host-return detach and
bailed the legitimate setup (or claude) write -- successful launch depended on
chunk grouping. Not the accepted identical-prompt exception (that supplies no
IN); here entry is genuinely proven. Closed in `35c531dc`: the hint now requires
known, distinct inner and host prompts before the prompt-only cancellation,
exactly as the idle hint does; current-attempt OUT cancellation stays
unconditional and a real detach with a distinct prompt still trips it. Four
regression tests (the two identical-prompt cases red before; a distinct-prompt
control; a distinct-prompt genuine-detach control proving the real protection
is intact); P2 mutation matrix `mutate-p2.py` 3/3 killed (including the
weakened-guard variant that keeps only `innerPromptLine !== ''`). Codex's own
8-case evidence test (`final-r1-extra.test.ts`) passes at this head. Full suite
10901 pass / 0 fail (884 files); typecheck + changelog clean. Codex confirmed
the two documented NOTEs (tmux bookkeeping published before submission; the
setup-catch latch held until the 10 s timeout) are follow-ups, not RC blockers.
