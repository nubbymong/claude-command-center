## 2026-08-22 -- #372: Ask Conductor gets its own Feature Guide entry

Book items 10 and 11. The issue carried three strands; only two were in scope to
build, and the third is deliberately left as a written proposal.

**Item 1 -- sidebar subtitle: already landed.** The owner's 2026-08-22 wording
("Ask about and customise app functionality", replacing "About this app") shipped
on `beta` in `1a5a1bf5`, with the tests in
`tests/unit/renderer/sidebar-dock-tips.test.tsx`. Verified in place rather than
re-implemented: the dock derives both the expanded subtitle and the collapsed
tooltip / accessible name from one `askSubtitle` constant, so the wording cannot
drift between the two rails.

**Item 2 -- the missing Feature Guide card.** The Feature Guide draws from two
sources: `APP_KNOWLEDGE_SECTIONS` (prose reference, also staged as the Ask
session's own `app-knowledge.md`) and `trainingSteps` (the feature cards). The
prose entry was under the current name, and the first pass certified it as
correct on that basis. Review caught that the *name* was current but the
*content* was not: it still told users to open Ask Conductor from "the button in
the footer", a control deliberately removed on the owner's 2026-08-21 call
("we dont need the one on the bottom bar", `BottomBar.tsx:113`). That string is
written verbatim into the Ask session's own `app-knowledge.md`, so the help
assistant was confidently directing users to a control that does not exist -- and
the shipped changelog already says there are *three* ways in and that the footer
button was removed before release. Four words deleted; the prose and the new card
now agree.

The *cards* had no Ask Conductor entry at all -- 20 cards, none for the help
surface itself. That is the same gap the Agent Canvas card closed earlier:
`FinishStep` promises the guide "explains every feature", and Ask Conductor was
the next feature missing from it. Added an `ask-conductor` card in
`getting-started`, third in the tour.

Two judgement calls worth recording:

- **`sinceVersion: '2.1.1'`, deliberately above the 2.1.0 cards.** The first pass
  pinned this at 2.1.0 on an inverted reading of the filter, caught in review.
  `getNewSteps()` keeps steps where `sinceVersion > lastVersion`, and
  `TrainingWalkthrough` stamps `lastTrainingVersion = currentTrainingVersion()`
  on close, so every beta user who has already run the 2.1 tour holds `2.1.0`.
  At 2.1.0 the card is filtered *out* for exactly that cohort and
  `shouldShowTraining()` returns false: the users who already have Ask Conductor
  and do not know what it does would never be shown it -- which is the discovery
  gap this issue was filed about. At 2.1.1 they are shown that one card and
  nothing else; the other 2.1.0 cards are not `> 2.1.0`, so the 2.1 set is not
  replayed (that was the false fear in the original note). Same move, same
  reason, as the `session-options` re-version. The badge is unaffected --
  `shortVersion()` renders both as "since 2.1". One cost: 
  `tests/e2e/first-launch-whats-new.spec.ts` hardcoded `lastTrainingVersion:
  '2.1.0'` to keep the tour suppressed while it exercises the What's-New/resume
  priority chain, and a bump would have armed the tour and changed what that spec
  tests. The literal is now derived from `currentTrainingVersion()`, so it cannot
  go stale again.
- **Screenshot reuses `v2-shell-hero.jpg`.** No capture of the Ask pill or the
  help session exists, and screenshots are captured on the VM and reviewed by the
  owner, so inventing one here was not an option. The reused shot is
  current-branding and shows both the sidebar the pill lives in and the `?`
  button that opens the guide; it was otherwise unreferenced, so nothing is
  duplicated. Follow-up capture noted inline as `step-ask-conductor.jpg`.

The retired name "Ask Command Center" survives on purpose and was left alone: the
historical 2.0 changelog entries (a record of what shipped), `ASK_LEGACY_LABEL`
in `lib/askConductor.ts` (used to recognise and retire the old saved config), and
four internal comments -- three pre-existing (`src/main/index.ts:678`,
`src/shared/ipc-channels.ts:240`, `src/renderer/utils/configHydration.ts:91`)
plus the new one on the card explaining the rename. A test asserts the old name
does not leak into any user-facing field of the card.

**Item 3 -- Sentinel/Logs reach: NOT built, proposal only.** The issue asks which
surfaces Ask Conductor may read and through what boundary. That is the owner's
call and an MCP/help-workspace change, so it takes the ADR-009 pass. Written up
as a scoped proposal comment on #372 (three options, security implications of
each, a recommendation) and explicitly marked as not built. Headless app control
is a separate 2.2 feature on #387 and is out of scope here.
