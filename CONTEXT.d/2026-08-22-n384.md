## 2026-08-22 -- #384 splash screen names the build (version, channel, sha, date)

**What changed.** The boot splash and Settings -> About now print one build
identity line, e.g. `v2.1.0-beta.17 · beta · build 3a1b2e2 · 2026-08-22`.

- `scripts/build-identity.mjs` resolves the short git sha at build time
  (`GITHUB_SHA` in CI, then `git rev-parse HEAD`, else `dev`) and one build
  timestamp; `electron.vite.config.ts` bakes them into BOTH main and renderer as
  `__BUILD_SHA__` / `__BUILD_TIME__` (the renderer already had `__BUILD_TIME__`;
  main now gets it too, from the same value).
- `src/shared/build-identity.ts` is the single formatter (`formatBuildIdentity`)
  plus the derivation helpers (`channelForVersion`, `shortSha`, `buildDate`).
  `renderer/utils/versionLabel.ts#defaultUpdateChannelForVersion` now delegates
  to `channelForVersion` so there is one definition of "which channel is this
  build on".
- Splash: the page is static file:// HTML with a strict CSP (no inline script,
  no preload), so main passes the line as the `build` query parameter of
  `loadFile` (`src/main/splash-info.ts#splashBuildQuery`); a new classic script
  `resources/splash/splash-info.js` reads it with URLSearchParams and sets
  `textContent` on a `#buildinfo` slot (between the loader label and the
  disclaimer; static, outside the animated layers -- no layout shift). It is a
  separate script from `splash.js` so the line still shows if three.js/WebGL
  fails.
- Settings -> About: the Build row now shows `<sha> · <time>` and a new
  `BuildIdentityLine` component renders the identical line in `--text-muted`.

**Why the channel comes from the version, not the `updateChannel` setting.**
The splash renders before any config is read, and "what build is this" should
not change when someone flips the update preference. Derivation mirrors the
updater's own tag classification (`-beta.N` / `-rc.N` -> beta, plain -> stable).
